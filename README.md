# 文本挖掘智能体

面向问卷、访谈、评论、新闻及业务文档，提供主题洞察、需求分析、情感与观点、质性研究、知识发现和证据报告等应用，由Agent组合工具完成实际文本挖掘任务。

## 当前状态

已完成面向文本挖掘应用的功能规划。当前仍为起始仓库，尚未实现分析工具、Agent或界面。

## 应用功能清单

完整的[应用功能清单](docs/FUNCTION_CHECKLIST.md)包括8类、24项功能：

1. **主题洞察：**发现主要议题、组织内容、识别新议题与少数声音。
2. **需求分析：**提炼困难与诉求、比较问题优先级、形成改进机会。
3. **情感与观点：**分析具体对象的评价、立场分歧及隐含表达。
4. **访谈研究：**辅助编码、解释经历、寻找反例与补访方向。
5. **知识发现：**整理事件、查询关系、比较典型情境与模式。
6. **证据问答：**按意思查找材料、跨文档问答、核查结论。
7. **变化分析：**比较群体与阶段、跟踪新材料和结论变化。
8. **专题研究：**Agent组织分析、生成图表报告、支持人工复核与迭代。

先完成“反馈与需求洞察”的完整应用，再按实际任务增加深入分析。技术原理与基础算法演示不作为独立产品功能；学生选择一项应用深入实现并验证效果。

## 目录结构

```text
docs/                 需求、数据说明与设计记录
src/                  后续实现代码
tests/                后续测试与评测代码
examples/             使用示例与演示入口
data/samples/         可公开的少量样例
data/raw/             本地原始数据，默认不提交
data/processed/       本地处理数据，默认不提交
.env.example          本地配置示例
```

## 开始工作

1. 阅读[需求与范围](docs/SCOPE.md)，明确本阶段要完成的功能。
2. 按[数据说明](data/README.md)准备材料和可共享样例。
3. 确定技术方案后补充依赖与启动方式，在`src/`逐步实现，在`tests/`保存对应验证。
4. 为结果保留来源与运行条件，区分教学示例、真实数据和实际模型输出。

当前没有安装、启动或模型调用步骤。技术栈、依赖管理与部署方式将在需求确认后确定；不要将目录骨架当作已可运行的应用。

## 配置与数据

如后续需要接口配置，可复制`.env.example`为`.env`并填写；当前代码不会读取这些变量。密钥、原始敏感数据和大型模型文件不提交到Git。`data/samples/`仅用于有权公开的小样例；外部代码、模型和数据按其各自许可使用。
