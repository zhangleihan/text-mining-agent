# 文本挖掘智能体

围绕明确的文本分析任务，组织资料处理、工具调用、证据核验和结果整理，研究智能体的有效性与可靠性。

## 当前状态

项目初始化版本。已建立独立Git仓库、目录结构和协作说明，尚未实现业务功能。具体功能、数据资源与技术方案将在后续需求明确后逐步补充。

## 初步研究方向

- 文本分析工具、状态与执行流程。
- 证据关联、异常处理与人工协作。
- 任务完成情况、执行轨迹和调用成本的评测。

以上为选题起点，具体范围以后续确认的需求为准。

## 目录结构

```text
docs/                 需求、数据说明与设计记录
src/                  后续实现代码
tests/                后续测试与评测代码
examples/             使用示例与演示入口
data/samples/         可公开的少量样例
data/raw/             本地原始数据，默认不提交
data/processed/       本地处理数据，默认不提交
.env.example          本地配置示例
```

## 开始工作

1. 阅读[需求与范围](docs/SCOPE.md)，明确本阶段要完成的功能。
2. 按[数据说明](data/README.md)准备材料和可共享样例。
3. 确定技术方案后补充依赖与启动方式，在`src/`逐步实现，在`tests/`保存对应验证。
4. 为结果保留来源与运行条件，区分教学示例、真实数据和实际模型输出。

当前没有安装、启动或模型调用步骤。技术栈、依赖管理与部署方式将在需求确认后确定；不要将目录骨架当作已可运行的应用。

## 配置与数据

如后续需要接口配置，可复制`.env.example`为`.env`并填写；当前代码不会读取这些变量。密钥、原始敏感数据和大型模型文件不提交到Git。`data/samples/`仅用于有权公开的小样例；外部代码、模型和数据按其各自许可使用。

## 推送到GitHub

本地分支为`main`，远程仓库尚未创建或绑定。在GitHub创建空仓库后执行：

```bash
git remote add origin <GitHub仓库地址>
git push -u origin main
```

本仓库尚未指定开源许可证。公开发布前由项目负责人确定授权方式。
