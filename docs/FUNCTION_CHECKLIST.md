# 文本挖掘智能体：应用功能清单

## 一、项目定位

面向问卷、访谈、评论、新闻、公告和业务文档，让用户提出实际分析问题，由Agent组织文本分析、证据查找、结果比较和报告生成，形成可用于研究或决策的成果。

功能围绕“发现了什么、为什么这样判断、能够怎样改进”组织。分词、向量化、模型调用等由底层工具按需完成；项目不设置编码、BPE训练、语言模型原理或参数演示等独立教学功能。

以下为规划中的8类、24项应用功能，当前均未实现。各组选择一个应用深入完成，不要求一次覆盖全部清单。

## 二、核心应用功能

### A. 主题发现与内容洞察

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| A01 | 发现主要议题 | “这些反馈主要在讨论什么？”归纳主题、子主题和覆盖情况，提供代表片段与未归类内容 |
| A02 | 组织材料与主题导航 | 将材料按主题和用户定义的类别组织，支持多标签、主题合并拆分及按主题浏览原始材料 |
| A03 | 发现新议题与少数声音 | 找出新增主题、异常表达和容易被整体总结忽略的意见，解释其与主要议题的关系 |

### B. 需求、痛点与改进机会分析

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| B01 | 提炼需求与困难 | 从反馈和访谈中提取“谁在什么任务中遇到什么困难、希望得到什么支持”，生成需求与问题清单 |
| B02 | 比较问题优先级 | 综合涉及人数、影响、具体情境和证据充分程度比较问题，给出透明的排序依据与待确认事项 |
| B03 | 形成改进机会 | 将问题对应到可采取的行动、适用对象及检查方式，区分受访者建议和系统提出的建议 |

### C. 情感、观点与立场分析

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| C01 | 分析具体对象的评价 | “学生对项目协作和考核分别怎么看？”识别评价对象、方面、态度及原因，保留褒贬并存情况 |
| C02 | 比较观点与分歧 | 围绕同一议题组织不同立场、论据和共识，展示分歧发生的条件及代表材料 |
| C03 | 理解隐含与复杂表达 | 结合上下文分析反讽、委婉不满、隐含诉求和语用意图，呈现可能解释及不确定性 |

### D. 访谈与质性研究辅助

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| D01 | 访谈编码与类别发展 | 对有上下文的片段辅助编码，维护代码定义，通过持续比较发展类别，保留人工修订和研究备忘录 |
| D02 | 解释经历与过程 | 从多份访谈中整理条件、行动、体验和结果，形成有依据的过程解释，并与自动发现的主题比较 |
| D03 | 寻找反例并建议补访 | 查找不支持当前解释的材料、证据空白与竞争解释，据此建议需要访谈的人群及中性追问 |

### E. 事件、情境与知识发现

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| E01 | 跨文档事件整理 | 从报道、公告等材料中整理主体、时间、行为、条件与结果，合并同一事件的不同描述并保留冲突 |
| E02 | 知识关联与关系查询 | 组织实体、事件、主题和来源的关联，回答“哪些对象有关、通过什么事件关联”，展示有依据的关系路径 |
| E03 | 典型情境与模式分析 | 比较反复出现的场景、条件、行为与结果组合，形成情境卡片、典型模式及反例 |

### F. 语义探索与证据问答

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| F01 | 按意思查找材料 | 根据自然语言问题、案例或描述找到语义相关材料，并对照相似与不同之处 |
| F02 | 跨文档证据问答 | 综合多份材料回答问题，每个重要结论关联来源，证据不足时说明不能判断 |
| F03 | 观点与结论核查 | 对给定结论检索支持、反对和限定条件，检查引用是否真实且足以支撑结论，生成待复核清单 |

### G. 群体、阶段与变化分析

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| G01 | 群体差异分析 | 比较不同基础、经历、来源或其他获准分组下的需求、主题与评价，说明共同点和差异 |
| G02 | 跨阶段变化分析 | 比较课前、课中、课后，或其他时间窗口的主题、期待与体验，区分持续问题、新问题和已缓解的问题 |
| G03 | 新数据追踪与更新 | 接入新增材料后检查原有结论是否仍成立，识别新证据与冲突，输出分析变化及需要修订之处 |

### H. 专题研究与成果生成

| 编号 | 应用功能 | 用户任务与预期成果 |
|---|---|---|
| H01 | 专题分析Agent | 根据用户问题制定可修改的研究计划，组合主题、观点、检索、比较等工具，补充证据并形成完整分析 |
| H02 | 图表与专题报告 | 生成有统计口径的图表和专题报告，组织主要发现、典型案例、不同意见、建议、来源及限制 |
| H03 | 分析复核与迭代 | 用户查看依据、纠正分类或解释、补充材料后更新结果，保留版本差异及结论修订原因 |

## 三、优先实现哪些应用

### 第一版：反馈与需求洞察

优先实现A01、B01、C01、F02、H01、H02、H03，完成一条可用流程：

**用户提出分析问题 → 导入反馈 → 发现议题、困难和评价 → 查找证据 → 人工检查 → 输出分析与建议。**

示例任务：“分析学生在课程实践中遇到的主要困难，对照支持需求提出改进建议，列出原文依据和不同意见。”

### 第二步：比较与深入解释

在真实任务驱动下增加访谈编码、反例、群体差异、阶段比较和观点核查，回答“哪些人有不同体验、为什么、证据是否充分”。

### 后续专项

按所选课题扩展事件图谱、风险情境、新数据追踪等能力。每组选择一项应用做深，提供完整示例与验证；不以实现多少个菜单作为目标。

## 四、Agent与公共支持能力

这些能力支撑上述应用，作为统一实现要求，不单列为面向用户的分析应用：

- 接入常见文本、表格和结构化资料，保留来源、版本、记录及片段定位。
- 允许人工操作分析功能，也允许Agent调用；提供任务进度、失败恢复和停止机制。
- 每项结果能回到材料，区分原文、模型概括与分析推断；保留人工修改。
- 统计由代码执行，图表标明单位、分母、缺失及多标签口径。
- 记录模型与方法版本、运行配置、调用成本和结果，支持复现及导出。
- 遵守数据的使用范围，对外部材料与工具权限分开处理。

## 五、与课程项目衔接

| 项目 | 可直接采用的应用组合 |
|---|---|
| 课程反馈与访谈分析 | 主题、需求与评价、质性解释、群体及阶段比较、教学改进报告 |
| AI风险知识图谱与洞察 | 事件整理、知识关联、情境与模式、证据问答、风险专题报告 |
| 每日趣闻智能体 | 议题发现、相似内容与事件整理、观点比较、新数据追踪；采集、兴趣推荐和富媒体输出在对应项目扩展 |
| 大模型量化选股与模拟交易 | 新闻及公告事件、情感与立场、证据核查、专题分析；组合、回测和模拟交易在对应项目扩展 |

课程方法在这些应用背后发挥作用，例如表示和重排支持材料查找，主题模型支持议题发现，大模型与深度学习分类支持评价分析，质性方法支持过程解释。技术选择和对照实验记录在实现与评测中。

## 六、验收与效果验证

每个应用至少交付一个真实任务示例、一份可运行实现、一批人工复核材料、基线比较和失败分析，说明成本及适用边界。

- **发现是否有价值：**有无遗漏重要需求、少数意见和反例，能否支持具体行动。
- **分析是否可信：**类别与情境是否准确，引用和统计是否正确，推断是否超过材料。
- **Agent是否有效：**比较人工操作、固定流程或直接大模型总结，检查任务完成、错误、时间及成本。
- **结果是否可改进：**人工纠正后能否更新分析，新增材料后能否解释结论变化。

研究中的限制要进入结果：访谈小样本不能直接推断总体比例；跨阶段差异不自动意味着因果；主题分组不等于扎根理论类别；关系共现不等于已验证机制。语用和隐含意图分析保留多种解释，避免把猜测当作事实。
